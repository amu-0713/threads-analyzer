# 分析輸出（`job_summaries`）

由 `src/pipeline/analysis.py` 產生。**每一項都有兩版**：`all`（真實 + mock）與 `real`（僅 `source='real'`）。沒有 mock 的任務兩版相同。

| 欄位 | 結構 |
|---|---|
| `metrics.{all,real}` | 篇數、平均/中位數（讚、回覆、轉發、引用、觀看、字數）、平均互動率、星期 × 時段分布（篇數與平均互動率）、文長與互動關係（分箱 + Spearman）、關鍵字（jieba，依「含該詞的貼文數」）、hashtag、貼文類型分布 |
| `top_posts.{all,real}` | 互動率前 5 名 |
| `group_analysis.{all,real}` | 分組規則、各組篇數、每篇貼文的組別（`assignments`）、每組 3–5 篇代表貼文，以及用同一套方法（關鍵字、類型、文長、提問/晚間/連結比例）對代表貼文做的比較 |
| `insights.{all,real}` | 三項假設檢定（提問句→回覆率、晚間→按讚率、含連結→互動率）+ 樣本數提醒 + 最佳時段 |
| `llm_advice` | 留空（之後的 LLM 建議用） |

## 定義

- 互動率 = (讚 + 回覆 + 轉發 + 引用) ÷ 觀看；按讚率 = 讚 ÷ 觀看；回覆率 = 回覆 ÷ 觀看
- 觀看數 ≥ 1 萬時 Threads 只顯示到千位（`views_rounded = true`），比率有約 ±5% 以內的誤差
- 晚間 = 台北時間 18:00–23:59；提問句 = 文字含 `？` 或 `?`（網址內的不算）

## 分組（PRD）

1. 觀看 < 該帳號觀看中位數的 20% → **未分組**（比率不可靠），也不參與百分位計算
2. 其餘貼文計算按讚率與回覆率在帳號內的百分位：`(比它小的篇數 + 0.5 × 相等的篇數) ÷ n`
3. **低迷型**：兩者 < 0.5；**討論型**：回覆百分位 ≥ 0.5 且 ≥ 按讚百分位；**共鳴型**：按讚百分位 ≥ 0.5 且 > 回覆百分位
4. 代表貼文：該組「最典型」的 3–5 篇（討論型取回覆百分位最高、共鳴型取按讚百分位最高、低迷型取兩者之和最低；組內不足 5 篇則全取）

`posts.group` 存的是 `all` 版的組別；`real` 版的分組在 `group_analysis.real.assignments`。

## 已知限制

- 真實貼文只有 5–8 篇，百分位與分組在這種樣本下很粗略（例如 7 篇就會有 2–3 篇各組）。
- 檢定用 permutation test（5,000 次，固定種子）；樣本少時 p 值不穩定，`insights` 在 n < 10 時會加註「僅供參考」。
- 關鍵字用 jieba 預設詞典，品牌名/新詞可能被切碎。
