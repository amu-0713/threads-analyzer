## 語意規則（v7–v9，同時寫在 prompt 與伺服器驗證裡）

| 規則 | 怎麼保證 |
|---|---|
| 中位數只寫方向或大約範圍；目標組較低往上取到十位（26 → 約 30 字左右以內）、較高往下取（89 → 約 80 字左右以上），不比資料更嚴 | prompt＋驗證（沒有「約／左右」或取整方向錯就退回） |
| 占比類特徵只寫「這篇要不要」有提問句／放連結／在晚間發；不可寫 X%、調整比例、增加／減少（summary、do、avoid 都一樣） | prompt＋驗證 |
| 驗證指標對應分組定義：共鳴型比按讚率中位數、討論型比回覆率中位數；不可寫觸及 | prompt＋驗證 |
| do 只依據目標組穩定特徵；低迷型只用在 avoid；do 的數字只用目標組自己的值 | prompt＋驗證（do 出現「低迷型」就退回）＋檢查腳本（其他側數值） |
| actions 數 = 目標組穩定特徵數，同一特徵不重複；只有 1 個就只給 1 點 | prompt＋驗證（點數）＋檢查腳本（重複） |
| 晚間 = 18:00–23:59，非晚間寫「18 點以前」 | prompt＋驗證（「23 點以後」退回） |
| avoid 寫成低迷型的寫法本身（「避開沒有提問句的貼文」），方向和低迷型一致，不寫「不要…」命令句 | prompt＋驗證 |

驗證不合格時帶原因重試一次，仍不合格就不存檔、畫面顯示原因（舊建議不會被覆蓋）。

## prompt 修正過程（全部只用 flash-lite 驗證）

| 版本 | 改了什麼 | flash-lite 結果 |
|---|---|---|
| v3 | 不可提素材；summary／do／avoid 也只能引用穩定清單 | why 常漏篇數與數值；有「以提升」「顯示…相關」語氣 |
| v4 | why／avoid 固定引用格式 | 模型用代表貼文關鍵字（「活動」）；avoid 一句混兩個特徵 |
| v5 | 不再把常見關鍵字送給模型；avoid 只依據一個特徵 | 剩「確保…以增加互動」 |
| v6 | 因果承諾改由伺服器驗證擋下 | 腳本乾淨，但**人工看全文**有語意問題（見下一列） |
| v7 | 中位數只寫範圍、占比只寫要不要、指標對應組別、do 只用目標組、點數＝特徵數、晚間定義、目標改名 | 腳本乾淨；人工發現取整方向錯（26 → 約 20 字以內，比資料更嚴）、avoid 寫成「不要使用提問句」方向相反 |
| v8 | 取整方向、avoid 寫成低迷型的樣子；驗證補上這兩項 | summary 寫「減少提問句」被驗證擋下，重試仍失敗 |
| v9 | summary 與 avoid 也只能寫要不要 | **7 / 7 產生成功，腳本 0 項，人工看過無違規** |

教訓：腳本檢查乾淨不代表語意正確（v6），每一版都要人工看全文；能寫成驗證的規則就寫成驗證（取整方向、avoid 方向、指標、點數），不要只靠 prompt。
